# RFab Viewer — "crashed" on Sep 28 was a freeze, not a crash (2026-09-29)

Diagnosed from `%TEMP%\rfab_viewer.log`, the Windows Application log, and
`Microsoft-Windows-Partition/Diagnostic` (disk attach/detach times).

## What actually happened

Nothing crashed. No traceback in the app log, no Application Error (1000) or
Application Hang (1002) event for `RFab Viewer.exe`, and every session's PyInstaller
temp folder was cleaned up normally. (Crash logging was confirmed working the same
morning with a deliberate `os.abort()`.)

The app **froze for 10-18 seconds at a time** while viewing a large folder on the
external card (`G:\f11`, attached 13:14:28, removed 13:30:19):

| Time | Action | Frozen for |
|------|--------|-----------|
| 13:19 | open `001.jpg` | 17.9 s, then 9 s and 10 s for the two extra windows the repeat double-clicks queued |
| 13:24:58 - 13:25:46 | five Left-arrow presses in a grid | 9-10 s each, 48 s back to back |
| 13:26 | open `008.jpg` | ~9 s |

Same signature on earlier days in `G:\AI Chat\cartoon` (18-20 s to open). On local
folders the same actions take ~0 s.

## Cause

`get_media_files()` listed the folder with `Path.iterdir()` and then called
`is_file()` on every entry. That is one file open per file, on the UI thread:
6,001 `stat` calls for a 6,000-file folder. On an SSD that is half a second; on a
USB card reader with on-access scanning each open costs a couple of milliseconds,
so the window stops responding for 10+ seconds. It ran

- every time a viewer opened (image or video), and
- on **every arrow-key press** in grid view, which rescanned the whole folder per press.

## Fixes

- `peek/utils.py` — `get_media_files()` uses `os.scandir()`, which takes the entry
  type from the directory listing. Zero per-file opens, identical result list.
- `peek/grid_view.py` — arrow-key navigation reuses the folder listing for 10 s
  (`_siblings_for`), so a run of key presses scans once.

Measured against the real viewer classes with a 6,000-file folder and a 1.5 ms
per-file stat (the slow drive, emulated):

| | before | after |
|---|---|---|
| open a viewer | 12.9 s | 0.16 s |
| 5 arrow-key presses | 63.5 s | 0.2 s |

## Logging, so the next report can be answered from the log

The old log could not say how a session ended. Now:

- every line carries date and pid (`09-29 06:04:20 [5480] ...`); the launch line
  carries the full timestamp and pid
- `CLOSE: <window> closed, N window(s) left` on every window close
- `EXIT: event loop ended, code=N` on a normal quit
- `UNHANDLED EXCEPTION` + traceback for exceptions raised inside Qt event handlers
  (the windowed build has no stderr, so these used to vanish)
- `faulthandler` writes the Python stack to the log on a native fault

A session whose last line is not `EXIT:` did not shut down normally.

`RFAB_VIEWER_IPC_PORT` overrides the single-instance port, so a test copy can run
without handing its files to the instance that is already open.

## Seen, not changed

- `_convert_to_grid` (image + video viewer) hides and `deleteLater()`s the window
  without unregistering it, so `_viewers` / `_all_viewers` / the boss key keep a
  dead object. `_maybe_quit` can never fire after a convert (Qt's own
  last-window-closed still quits), and the manual-drag merge check can touch a
  deleted window.
- The IPC socket sets `SO_REUSEADDR`, which on Windows lets a second instance bind
  the same port instead of failing.
- Flatten / dedup / unzip still stat every file (`rglob` + `is_file`). They show
  progress, but will be slow on the same kind of drive.

## Files changed
- `peek/utils.py`, `peek/grid_view.py` — the fix
- `peek/main.py`, `peek/resizable.py` — logging, IPC port override

Rebuilt via `python -m PyInstaller "RFab Viewer.spec"`; previous build kept as
`dist\RFab Viewer.prev.exe`.
